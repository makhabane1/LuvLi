# Luvli ♡ — making the two real integrations live

Luvli works perfectly with nothing here configured. This guide turns on the two
things that need _your_ accounts, because neither can be done for you:

1. **Real Google sign-in** — needs a Google OAuth client ID.
2. **A real AI coach** — needs a model API key.

Both are optional. Both take about five minutes. Neither one requires you to
understand the code.

> **Why can't this be done automatically?** Creating those credentials means
> signing into Google Cloud and OpenAI/Anthropic with _your_ account and
> accepting _their_ terms. No script can do that on your behalf — and any key
> generated by someone else simply would not work. So Luvli gives you a setup
> that asks for the values once and writes them into the right files.

---

## First, the one command to remember

```bash
npm run dev
```

That starts the whole app **and** a working coach endpoint on your machine:

|                |                                       |
| -------------- | ------------------------------------- |
| App            | http://localhost:8080                 |
| Sign in        | http://localhost:8080/login.html      |
| Coach          | http://localhost:8080/ai-coach.html   |
| Coach endpoint | http://localhost:8080/api/luvli-coach |

At this point everything already works — sign-in uses the honest local account,
and the coach uses its on-device brain. You can stop reading here and Luvli is
completely usable. The rest is only if you want the "real" versions.

---

## The quick way: the setup helper

```bash
npm run setup
```

It asks three questions and edits the files for you:

```
  1) Real Google sign-in
     Client ID (…apps.googleusercontent.com):  ← paste it here
  2) Real AI coach
     Coach endpoint [/api/luvli-coach]:        ← press Enter for local
  3) Your model API key
     API key:                                  ← paste it here
```

Press **Enter** on any question to skip it. Then run `npm run dev`.

The manual steps below are exactly what that script does, if you would rather do
it yourself or want to understand it.

## 1 · Real Google sign-in

### Get a client ID

1. Go to **[console.cloud.google.com](https://console.cloud.google.com/)** and sign in.
2. At the top, **select or create a project** (any name — "Luvli" is fine).
3. Open the menu → **APIs & Services** → **OAuth consent screen**.
   - Choose **External**, click **Create**.
   - Fill in an app name ("Luvli") and your own email.
   - Save and continue through the remaining steps. You can leave the scopes
     and test users alone.
4. Open the menu → **APIs & Services** → **Credentials**.
   - Click **Create credentials** → **OAuth client ID**.
   - Application type: **Web application**.
   - Under **Authorised JavaScript origins**, click **Add URI** and add:
     - `http://localhost:8080`
     - (later, also your real site, e.g. `https://luvli.example.com`)
   - Click **Create**.
5. A box appears with your **Client ID** — it looks like
   `1234567890-abc123def.apps.googleusercontent.com`. Copy it.

> A client ID is **public** and safe to commit. There is no client _secret_
> needed — Luvli is a browser app and never uses one.

### Paste it in

Open `js/auth-config.js` and put it here:

```js
var google = {
  clientId: "PASTE-YOUR-CLIENT-ID-HERE.apps.googleusercontent.com",
  gisSrc: "https://accounts.google.com/gsi/client",
};
```

**That's it.** Reload `login.html`, click **Continue with Google**, and Google's
own account chooser appears. If Google cannot be shown for any reason (an
unauthorised origin, blocked cookies, offline), the button falls back to the
labelled local account after a few seconds instead of hanging.

### How to know it worked

Open `http://localhost:8080/login.html`, press **F12** → **Console**, and run:

```js
window.LuvliAuthConfig.hasGoogle(); // → true once your client ID is in
```

If it says `false`, the client ID did not match the
`…apps.googleusercontent.com` shape.

## 2 · The real AI coach

The coach talks to a small function that you deploy. The function holds your
model key so the browser never sees it. There is a **working one already
written** in this repo.

### Get a model key

- **OpenAI** — [platform.openai.com/api-keys](https://platform.openai.com/api-keys) → _Create new secret key_
- **Anthropic** — [console.anthropic.com/settings/keys](https://console.anthropic.com/settings/keys) → _Create key_

Copy the key. (For OpenAI it starts with `sk-`.)

### Try it locally first — no deploy needed

`npm run dev` already runs the coach function. Put the key in a file:

1. Copy the example: `copy .env.example .env` (Windows) or `cp .env.example .env`
2. Open `.env` and fill in your key:

```ini
COACH_API_KEY=sk-your-real-key-here
COACH_PROVIDER=openai
```

3. Tell the page to use it — open `js/coach-config.js`:

```js
  var coach = {
    mode: 'model',
    endpoint: '/api/luvli-coach',
```

4. Restart `npm run dev`, open the coach page, and send a message.

You will see a line under the composer telling you plainly which coach is
answering — the on-device one, or your model. That line never lies.

> `.env` is already listed in `.gitignore`, so your key cannot be committed by
> accident.

### Deploying it (when you want it online)

**Netlify** — the config is already written (`netlify.toml`):

1. Push this folder to a Git repo and connect it to Netlify.
2. Netlify → **Site settings → Environment variables** → add `COACH_API_KEY`
   (and optionally `COACH_PROVIDER`, `COACH_MODEL`, `LUVLI_ALLOWED_ORIGIN`).
3. Deploy. The function appears at `/api/luvli-coach`.

**Vercel** — use the copy at `api/luvli-coach.js`:

1. Connect the repo to Vercel.
2. Vercel → **Project → Settings → Environment Variables** → add `COACH_API_KEY`.
3. Deploy.

Then set `endpoint` in `js/coach-config.js` to your live URL and remove
`LUVLI_ALLOWED_ORIGIN`'s blank default by setting it to your domain.

### The safety guarantee

The coach is **fail-soft on purpose**. If your key is missing, the model errors,
or the network drops, the function returns `{ degraded: true }` and the page
quietly falls back to its on-device brain. The coach never goes dead because a
call failed — you will just notice the reply did not come from the model.

## Any time you want to switch back

Change `js/coach-config.js` back to `mode: 'local'`, blank the `clientId` in
`js/auth-config.js`, and delete `.env`. Luvli returns to being a fully offline,
local-first app — which is its default and always its healthy state.

## Checking nothing broke

```bash
npm run verify
```
